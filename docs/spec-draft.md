# シェアハウス共用アプリ 仕様書（ドラフト）

Sep 27, 2026 · @zozo

## 概要と目的

最大8人の多国籍シェアハウスで、掃除当番・共用設備の利用・連絡を1つのアプリにまとめ、言葉の壁による行き違いを減らす。

- 掃除の分担を公平にし、誰がいつ何をやったか見えるようにする
- 洗濯機の「空いてる？」を聞かずに分かるようにし、消耗品の買い出しと共用費（月500円）も見える化する
- 大事な連絡を各自の言語で確実に届ける

## 利用者と前提条件

利用者は留学生と日本人の住人で、1つのハウスにつき最大8人。各自が自分のスマホにアプリを入れ、自分で選んだ言語で使う。

- LINE・大学メール・日本の電話番号は全員が持っているとは限らないため、ログインや通知には使わない
- 住人は入れ替わる（入居・退去の操作が必要）
- 管理人（大家・管理会社）はアプリを使わない前提（要確認）
- 対応言語：日本語・英語の2言語

6. 各自の完了回数・代行回数を表示

#### サボり対策

責めるより「忘れていた」を防ぐことを優先し、通知は段階的に強くする。

1. ゴミ出し担当：前夜20時と当日朝7時に本人へ通知
2. ゴミ出し当日の9時までに完了がなければ、その週「休み」の人に代行のお願いを通知
3. その他の担当：木曜20時と日曜10時に未完了なら本人へ通知
4. 週が終わっても未完了なら、当番表に「未完了」と表示（全員に見える）。通知は本人にだけ送り、全員への一斉通知はしない
5. 未完了が続く場合の扱い（翌週もう一度担当するなど）は住人で話し合って決める

### 2. 洗濯機（MVP）

1. 使う人が「使用中にする」ボタンを押す（終了予定時刻の入力は任意）
2. 取り出したら「空いた」ボタンで全員に通知
3. 終了予定時刻を入れた場合は、その時刻に本人へ通知
4. 終了予定から30分たっても「空いた」が押されていなければ本人にリマインド
5. 予約機能は作らない

### 3. 連絡・掲示板（MVP）

1. 全員あての投稿（ゴミ出しルール変更、来客予定、修理業者が来る日など）
2. 投稿は各自の言語に自動翻訳して表示。原文も切り替えて見られる
3. 重要な投稿はプッシュ通知も送り、「読んだ」ボタンで既読を確認
4. よく使う連絡はワンタップの定型文（例：「トイレットペーパーが切れました」）

### 4. 買い物帳と共用費（第3段階）

消耗品が切れたら買い物帳に書き、行ける人が手を挙げて買い、金額を記録する。お金は毎月1日に集める共用費（1人500円、8人で月4,000円）から払う。

| 状態 | 誰が | すること |
| --- | --- | --- |
| 未対応 | 気づいた人 | 品名を書く（写真・メモは任意）。トイレットペーパー、ゴミ袋、洗剤、スポンジなどは定型ボタンで追加 |
| 担当中 | 買いに行ける人 | 「行けるよ」を押す。最初に押した1人が担当になり、書いた人に通知 |
| 完了 | 買った人 | 「完了」を押して金額（円）を入力。レシート写真は任意 |
| 精算済み | 会計担当 | 立て替えた金額を共用費から払ったら押す |

- 3日たっても誰も「行けるよ」を押さなければ、全員に再通知

共用費：

1. 毎月1日に全員へ「今月の共用費500円」を通知
2. 払ったかどうかは各自が「払った」ボタンで自己チェックする。払った人数（例：6/8人）を表示
3. 5日20時の時点で自己チェックがなければ、本人にだけ通知
4. 月ごとの残高を一覧で表示する。今月の残高はホームにも表示

| 月 | 前月からの繰越 | 集まった額 | 使った額 | 月末の残高 |
| --- | --- | --- | --- | --- |
| （例）10月 | 0円 | 4,000円（8人） | 2,350円 | 1,650円 |
| （例）11月 | 1,650円 | 3,500円（7人） | 3,100円 | 2,050円 |

集まった額は自己チェックした人数×500円、使った額はその月に「完了」になった買い物の合計で自動計算する。

### 5. 住人管理と言語（MVP）

1. 招待コードでハウスに参加
2. 退去時にメンバーから外し、当番を再割り当て
3. 表示言語は各自が設定で選ぶ（スマホの言語を初期値にする）

## デザイン

[デジタル庁デザインシステム（DADS）](https://design.digital.go.jp/dads/)を参考に、落ち着いたオレンジをメインカラーにする。

- メインカラー：DADSのカラーパレットにあるオレンジの階調から、落ち着いた（やや暗めの）段階を選ぶ
- 背景は白。文字とボタンは白地に対してコントラスト比4.5:1以上（DADSの基準）
- 文字サイズは16px以上、スマホ縦画面優先、ボタンは大きめ
- 色だけで意味を伝えない。当番の種類は色＋文字（T、Kなど）で表示
- DADSは出典を明記すれば民間でも使える。利用条件を確認し、設定画面の下などに出典を記載する
- DADSはAIが読みやすいMarkdown形式の資料も配布しているので、Claude Codeに読み込ませると精度が上がる

## 技術構成

Next.jsのWebアプリ（PWA）をClaude Codeで作り、GitHubに保管してVercelで公開する。

| 役割 | 使うもの | 補足 |
| --- | --- | --- |
| アプリ本体 | Next.js（App Router、TypeScript） | ホーム画面に追加できるPWAにする |
| コード保管 | GitHub | リポジトリ1つ |
| 公開 | Vercel（無料のHobbyプラン） | GitHubと連携し、更新すると自動で反映 |
| データ保存・ログイン | Supabase（無料枠） | データベースと匿名ログイン（Auth） |
| 定時処理 | Supabaseの定時処理（pg\_cron）＋Edge Functions | 数分おきに実行。VercelのCronは使わない |
| 通知 | Web Push（プッシュ通知） | 次の「通知の仕組み」を参照 |

- 規模：1ハウス最大8人なので、無料枠で足りる見込み
- 時刻：画面は日本時間で表示
- データはハウス単位で分け、住人以外は見られない

## アカウントとログイン

Supabaseの匿名ログインを使い、「招待コード＋名前」だけで参加できるようにする。メール・電話番号・パスワード・PINは使わず、スマホが自動でログイン状態を覚える。

| 項目 | 決めたこと |
| --- | --- |
| ログイン方式 | Supabaseの匿名ログイン。端末ごとに自動でアカウントが作られ、住人データとひも付ける |
| 参加に必要なもの | 6桁の招待コード（QRコード付き・有効期限7日）と名前、表示言語 |
| 機種変更・アプリ削除 | 代表者が「引き継ぎコード」（有効期限24時間）を発行し、新しい端末で入力すると元の住人データに戻れる |
| 権限 | 代表者（2人以上）：設備・掃除ルールの設定、招待・引き継ぎコードの発行、退去処理。住人：それ以外の操作 |
| 見られる範囲 | Supabaseの行レベルセキュリティ（RLS）で、自分のハウスのデータだけ読み書きできる |
| 退去 | 代表者がメンバーから外すと、その端末からはハウスのデータが見られなくなる |

参加の流れ：

1. 代表者がハウスを作成し、設備と掃除場所を設定
2. 招待コードを直接見せるか、QRコードを共用スペースに貼る
3. iPhoneの人は先にSafariでアプリを開き「ホーム画面に追加」、そのアイコンから開き直す（Androidはそのままで可）
4. 招待コードを入力 → 名前と言語を選ぶ → 通知を許可して参加完了

- iPhoneはSafariで開いたときとホーム画面から開いたときでログイン情報が別になるため、必ずホーム画面のアイコンから参加してもらう。アプリ側でも、ホーム画面から開いていないiPhoneには参加前に案内を出す
- 代表者が全員退去しそうなときに備え、代表者は常に2人以上いるようにアプリで制限する

## 翻訳の方針

日本語と英語の2言語だけにし、翻訳チェックの手間をなくす。

- 画面の文言・定型文・通知：日本語と英語を最初から用意（作る側で確認できる範囲）
- 掲示板の自由投稿：日英を自動翻訳し、原文も併記
- 文言は言語ファイルにまとめておき、将来ほかの言語を足したくなったら追加できる作りにする

## 通知の仕組み

Webアプリでもプッシュ通知は送れる。定時の通知はSupabaseの定時処理で数分おきに送る時刻が来たものを確認して送るので、洗濯終了のような分単位の通知も無料で扱える。iPhoneは「ホーム画面に追加」したアプリからしか受け取れない。

| 通知 | 送る相手 | タイミング | 仕組み |
| --- | --- | --- | --- |
| 掲示板の重要投稿 | 全員 | 投稿した瞬間 | 操作をきっかけに即送信 |
| 洗濯機が空いた | 全員 | 「空いた」を押した瞬間 | 操作をきっかけに即送信 |
| 当番の交換・代行のお願い | 相手 | 依頼した瞬間 | 操作をきっかけに即送信 |
| 洗濯の終了 | 本人 | 終了予定時刻（入力した場合） | Supabaseの定時処理（5分おき） |
| 洗濯物の放置 | 本人 | 終了予定から30分後 | Supabaseの定時処理 |
| ゴミ出し | 月・木・水金の担当（水金は収集がある日のみ） | 前夜20時と当日朝7時 | Supabaseの定時処理 |
| ゴミ出しの代行お願い | その週「休み」の人 | 当日9時に未完了なら | Supabaseの定時処理 |
| 掃除の未完了 | 本人 | 木曜20時と日曜10時に未完了なら | Supabaseの定時処理 |
| 今週の当番 | 全員 | 日曜朝9時（週の切り替え時） | Supabaseの定時処理 |

第3段階で追加する通知：

| 通知 | 送る相手 | タイミング |
| --- | --- | --- |
| 買い物帳に追加された | 全員 | 追加した瞬間 |
| 「行けるよ」が押された | 書いた人 | 押した瞬間 |
| 誰も「行けるよ」を押していない | 全員 | 追加から3日後 |
| 今月の共用費 | 全員 | 毎月1日 9時 |
| 共用費の未払い | 本人 | 毎月5日 20時に未払いなら |

1つ目の表の通知は第2段階、2つ目の表（買い物帳と共用費）の通知は第3段階で作る。

- iPhone（iOS 16.4以降）はSafariで開き「共有 → ホーム画面に追加」してから、そのアイコンで開いて通知を許可する必要がある
- 初回起動時に、iPhoneの人向けに追加方法を図で案内する画面を出す
- Androidはブラウザのままでも通知を受け取れる
- 通知が届かない人もいる前提で、ホーム画面に未読・今日の当番を必ず表示する

## 開発の進め方

一度に全部頼まず、3段階に分けてClaude Codeに指示する。段階ごとにGitHubへ上げ、Vercelで動作確認してから次へ進む。

1. 第1段階：画面・データ保存・掃除当番・洗濯機・掲示板・参加の仕組み（通知なし）
2. 第2段階：プッシュ通知（即時通知＋毎日1回の当番リマインド）
3. 第3段階：買い物帳と共用費、掲示板の自動翻訳

事前の準備（開発する人のアカウント）：

1. GitHubアカウントを作る
2. VercelとSupabaseに「GitHubでログイン」で登録する
3. Supabaseで新しいプロジェクトを作る（地域は東京）。設定画面の「Authentication」で匿名ログイン（Anonymous sign-ins）をオンにする
4. SupabaseのプロジェクトURLとキーをVercelの環境変数に登録する（どの値をどこに入れるかはClaude Codeに聞けば教えてくれる）
5. 第2段階では通知用の鍵（VAPIDキー）も必要。Claude Codeに作り方を案内してもらう
